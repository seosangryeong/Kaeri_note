!!! summary "한 줄 요약"
    Isaac Lab 포크(`IsaacLab_snake`)에서 과제를 여러 번 바꿨다. "목표 위치로 가라"로 시작해 머리 카메라로 상자를 보게 하는 과제, 몸 순서 리워드, CPG 액션, 관절마다 에이전트를 둔 셀프어텐션 정책을 거쳐, **정책이 정현파 보행의 진폭과 위상 방향만 고르고 속도 명령을 따라가는** 최종 구조에 도착했다. 그 뒤 위치 추종과 미로 경로 주행으로 넓혔다.

## 단계별 정리

| 단계 | 액션 | 커맨드 | 핵심 리워드 | 메모 |
|---|---|---|---|---|
| 1 | 사인파 파라미터 (평면별 진폭 범위·주파수·위상 계수) | 목표 위치 | 위치 오차, tanh 위치 오차, 똑바로 섬 | 처음 구조 |
| 2 | 사인파 파라미터 | 목표 위치 | 위치 오차, 방향 오차, 액션 변화 | 액션 스케일을 여러 번 조정 |
| 3 | 사인파 + 관절 위치 | 목표 위치 + **머리 목표** | 머리 카메라 방향 정렬, 상자 높이·정렬, 머리 위아래 속도 벌점 | 머리로 상자를 바라보게 하는 과제 |
| 4 | 사인파 | 목표 위치 | 위치 오차, 똑바로 섬, **몸 순서 리워드** | 몸을 떨면서 조금씩 움직임 |
| 5 | **CPG 액션** (진폭 중심, 주파수, 위상차, 오프셋 7개) | 목표 위치 | 목표 쪽 진행, 상자 x축 정렬, 거리 | |

| 8 | 사인파 | **속도 명령** | 진행 속도 추종 | 과제를 속도 명령으로 바꿈 |
| 9 | 사인파 (진폭 16 + 위상 방향 2) | 속도 명령 (**월드 고정**) | 방향 정렬, 속력 일치, 똑바로 섬 | 최종 속도 추종 정책 (기록 4) |
| 10 | 사인파 | **목표 지점** + 미로 경로 | 거리, 목표 방향 정렬, 평균 속력 | 최종 위치 추종 정책 (기록 5) |

## 주요 시도

### 머리 카메라와 상자 (3단계)

뱀 머리의 카메라가 상자를 바라보게 하는 과제를 만들었다. 머리 위치·자세를 관측할 수 있게 Isaac Lab의 관절체 데이터에 머리 위치와 쿼터니언 속성을 추가했고, 커맨드에는 몸 목표와 머리 목표를 따로 뒀다. 리워드는 카메라 방향 정렬, 상자 높이, 머리가 위아래로 흔들리는 속도 벌점이었다.

### 몸 순서 리워드 (4, 6단계)

머리 → `Link1` → … → `Link15` → 꼬리 순서로 목표에 가까워야 한다는 리워드다. 몸이 꼬이거나 꼬리가 먼저 나가는 자세를 막으려고 넣었다. 이동 + 몸 순서 + 똑바로 섬 조합으로 학습하니 몸을 약간 떨면서 움직였다.

### CPG 액션 (5단계)

정책이 관절 각도 대신 CPG의 목표 파라미터 7개를 정하게 했다.

| 파라미터 | 기준값 | 뜻 |
|---|---|---|
| 수평 진폭 중심 | 0.75 | [0, 1.5] 범위의 가운데 |
| 수직 진폭 중심 | 0.75 | |
| 주파수 ω | 6.28 (1 Hz) | 기준을 유지하고 변화량만 제어 |
| 수평 위상차 | 0 | [−π, π] |
| 수직 위상차 | 0 | |
| 좌우 회전 오프셋 | 0 | |
| 상하 자세 오프셋 | 0 | [−0.1, 0.1] |

CPG는 위상과 진폭을 매 스텝 적분하므로 출력이 연속이다. 대신 목표 파라미터가 바뀌어도 실제 궤적이 따라오는 데 과도 응답 시간이 걸린다. 급하게 방향을 바꿔야 할 때 한 박자 늦는 이 문제 때문에, 최종 구조는 명시적인 정현파 함수로 정했다.

### 셀프어텐션 정책 (7단계)

관절 16개를 각각 "에이전트"로 보고, 에이전트마다 관절 토크 하나를 내는 액션(`ModularJointEffortAction`)과 셀프어텐션 정책 네트워크를 만들었다. RSL-RL 설정에 `RslRlSelfAttentionCfg`를 추가했다.

| 항목 | 값 |
|---|---|
| 에이전트 | 16 (관절마다 1) |
| 잠재 차원 | 128 |
| 어텐션 헤드 | 2 |
| 인코더 층 | 1 |

관절끼리 어텐션으로 정보를 주고받는 구조라 관절 수가 바뀌어도 같은 네트워크를 쓸 수 있다. 하지만 관절 토크를 직접 내는 방식은 탐색 공간이 커서, 바퀴 없는 3차원 뱀로봇에서 안정적인 파형을 만들기 어려웠다. 다음 단계에서 사인파 액션 + MLP로 돌아갔다.

### 움직임 군집화

정책이 어떤 움직임 유형을 쓰는지 보려고, 에피소드별 액션 시퀀스를 KMeans로 64개 군집으로 나누고(`clustering.py`), 각 군집 중심 시퀀스를 64개 환경에서 동시에 재생해 확인하는 도구(`clustering_review.py`)를 만들었다.

## 트러블슈팅

!!! issue "몸이 진동하면서 조금씩만 움직임"
    **문제** 위치 목표 + 몸 순서 + 똑바로 섬 리워드로 학습한 정책이 몸을 떨면서 조금씩 움직였다.

    **원인** 위치 리워드는 "목표에 가까워짐"만 보기 때문에, 크게 기어가는 보행과 작은 진동으로 미끄러지는 움직임을 구분하지 못했다.

    **해결** 목표 쪽 진행 리워드를 추가하고, 이후 과제를 속도 명령으로 바꿔 몸 전체 평균 속도의 **방향과 크기**를 직접 보상했다(기록 4).

!!! issue "머리 좌표축이 돌아가 있어 똑바로 섬 판정이 틀림"
    **문제** 똑바로 섬 리워드가 실제 자세와 맞지 않았다.

    **원인** 뱀로봇 모델의 머리 링크 좌표축이 돌아가 있어서, 머리 z축과 월드 z축의 내적이 "위를 보고 있음"을 뜻하지 않았다.

    **해결** 뱀로봇용 판정 함수(`base_up_proj_kanake`)를 따로 만들어 머리 좌표축에 맞는 축으로 계산했다.

!!! lesson "배운 점"
    - 관절 토크, CPG를 거쳐 결국 **정현파 보행 파라미터를 내는 액션**으로 정했다. 파형의 모양은 정현파 구조로 고정하고, 정책은 진폭과 방향만 조절한다. 탐색 공간이 줄어 학습이 안정되고, 미분방정식이 없어 반응도 즉각적이다.
    - 몸 전체가 움직이는 로봇은 머리 하나의 위치·방향으로 성과를 재면 흔들림 때문에 틀어진다. 몸 전체 평균 속도처럼 **몸 전체를 보는 지표**가 필요했다.
