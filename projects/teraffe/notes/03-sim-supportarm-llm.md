!!! summary "한 줄 요약"
    차체에 지지팔(좌우 회전, 관절 2개, 2단 신축)을 달고, 조이스틱 Y 버튼으로 주행 모드와 팔 모드를 오가게 했다. 같은 노드에 로컬 LLM(Ollama gemma3:4b) 채팅창을 붙여 "앞다리를 1m로 올려줘" 같은 말을 관절 값으로 바꾸게 했고, 마우스로 방향을 찍어 주행하는 GUI도 만들었다.

## 한 일

- 관절 21개 명령: 주행 16개 + 지지팔 5개 (`teraffe_supportarm_control`)
- Y 버튼 토글로 **주행 모드 ↔ 팔 모드** 전환. 모드를 바꾸면 다른 쪽 입력을 0으로 지워 멈춤
- 앞다리·뒷다리 높이를 따로 조절 (십자패드 상하, X·A 버튼)
- 로컬 LLM function calling 채팅창 (`..._functioncalling`, PyQt5)
- 포인트 앤 클릭 주행 GUI: 마우스 우클릭 방향으로 주행, 스페이스바 정지 (`..._gui`)

## 팔 모드 조이스틱

| 입력 | 동작 |
|---|---|
| 십자패드 좌우 | `arm_pivot` 좌우 회전 |
| 왼쪽 스틱 상하 | `arm_j1` |
| 오른쪽 스틱 상하 | `arm_j2` |
| LB / RB | 팔 줄이기 / 늘리기 |
| B | 팔과 다리 전부 초기화 |

관절은 매 0.1초 `입력 × 0.04 rad`씩 움직인다. 신축은 총 길이 하나(0 ~ −2.2 m)로 관리하고, **1단(`ext1`)이 먼저 −1.1 m까지 늘어난 뒤 2단(`ext2`)이 늘어나게** 나눠서 보낸다. 다리 2단 리프트와 같은 방식이다.

## 로컬 LLM으로 명령하기

사용자가 채팅창에 말로 쓰면, LLM이 정해진 JSON 형식으로 "어떤 함수를 어떤 값으로 부를지"를 답하고, 노드가 그 값을 상태에 넣는다. 다음 0.1초 주기에 그대로 관절 명령으로 나간다.

1. 현재 상태(팔 관절 4개, 다리 높이 2개, 주행 입력 4개)를 `[시스템 정보]`로 붙여 사용자 문장과 함께 보낸다.
2. 시스템 프롬프트에 함수 두 개의 이름, 입력 범위, 출력 JSON 예시를 적어 둔다.
3. 답에서 코드 블록 표시(```json)를 벗겨 내고 JSON으로 읽는다.
4. `tool_call.name`에 따라 값을 반영한다. JSON이 아니면 그냥 대화로 보여 준다.
5. 반영한 값을 LLM에 한 번 더 보내 사람이 읽기 쉬운 문장으로 요약해 받는다.
6. `duration`이 있으면 그 시간만큼 주행을 유지한 뒤 주행 입력을 0으로 돌린다.

| 함수 | 인자 |
|---|---|
| `control_robot_arm` | `arm_pivot`, `arm_j1`, `arm_j2`, `arm_ext_total` (0 ~ −2.2) |
| `control_robot_drive` | `height_front`, `height_back` (0 ~ 1.6), `drive_axis_val`, `steer_axis_val`, `turn_axis_val`, `pivot_axis_val`, `duration` |

```json
{"tool_call": {"name": "control_robot_drive",
  "arguments": {"height_front": 0.0, "height_back": 0.0, "drive_axis_val": 1.0,
                "steer_axis_val": 0.0, "turn_axis_val": 0.0, "pivot_axis_val": 0.0,
                "duration": 1.0}}}
```

LLM 추론은 별도 스레드(QThread)에서 돌려서 채팅창과 ROS 주기가 멈추지 않게 했다.

## 포인트 앤 클릭 주행 GUI

원 모양 가상 패드에서 마우스 오른쪽 버튼을 누른 위치가 곧 스틱 입력이다. 중심에서 위로 갈수록 전진, 좌우로 갈수록 조향이 커지고, 원 밖을 누르면 원 둘레로 잘라서 −1 ~ 1로 맞춘다. 버튼을 놓아도 그 방향으로 계속 가고, 스페이스바를 누르면 멈춘다.

## 트러블슈팅

!!! issue "LLM이 말하지 않은 값까지 바꿈"
    **문제** "앞다리만 올려줘"라고 해도 다른 관절이나 높이가 임의의 값(예: 0.5)으로 바뀌어 나왔다.

    **원인** 출력 JSON은 모든 인자를 채워야 하는데, 모델이 현재 값을 모르니 그럴듯한 값을 지어 넣었다.

    **해결** 매 요청에 현재 상태를 붙이고, 프롬프트에 "요청하지 않은 항목은 현재 상태 값을 그대로 출력하라"는 규칙을 넣었다.

!!! issue "회전 관절에서 시뮬 물리 오류"
    **문제** 지지팔 회전 관절을 한 방향으로 계속 돌리면 시뮬레이터 물리 엔진(PhysX)에서 오류가 났다.

    **원인** 관절 목표 각도가 ±2π를 넘어 계속 쌓였다.

    **해결** 회전 관절 세 개의 목표를 `±(2π − 0.01)` 안으로 자른다.

!!! lesson "배운 점"
    - LLM에게 "값을 정하게" 하려면 현재 상태를 같이 줘야 한다. 모르는 값은 지어낸다.
    - LLM 출력은 그대로 믿지 말고 JSON 파싱 실패, 모르는 함수 이름을 따로 처리한다. 지금은 범위 검사가 없어서 다음에 넣을 부분이다.
    - 모드 전환을 할 때는 다른 모드의 입력을 지워야 이전 모드의 동작이 남지 않는다.

## 원리

??? Function calling을 흉내 내는 방법
    도구 호출 기능이 없는 작은 로컬 모델도, 프롬프트로 출력 형식을 강하게 정해 주면 비슷하게 쓸 수 있다.

    1. **함수 설명:** 이름, 하는 일, 인자와 범위를 글로 적는다.
    2. **출력 형식 고정:** "함수를 부를 땐 다른 말 없이 이 JSON만 출력하라"와 예시 하나.
    3. **파싱과 실행은 코드가:** 모델은 값만 정하고, 실제로 상태를 바꾸는 건 노드다.
    4. **결과 요약:** 실행한 값을 다시 모델에 주고 자연어로 설명하게 한다.

    모델이 형식을 어기면(코드 블록 표시, 설명 문장 섞임) 파싱이 깨지므로, 앞뒤 표시를 벗기고 실패하면 일반 답으로 처리한다.
