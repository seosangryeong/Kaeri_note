!!! summary "한 줄 요약"
    Teraffe 위 로봇팔로 **실물 밸브를 돌리기** 위해, 연구실의 Franka Research 3(FR3)에서 "손목 카메라로 목표를 찾고 → 로봇 좌표로 옮기고 → 정렬해서 곧게 다가가 잡는" 과정을 만들었다. 카메라는 처음에 트레이 위에 고정(eye-to-hand)했다가, 팔이 시야를 가리는 문제 때문에 손목(eye-in-hand)으로 옮겼다. 목표물(40 mm 큐브)을 깊이 영상에서 평면으로 찾아 위치와 회전각을 구하고, 바로 위에서 한 번 더 본 뒤 직선으로 내려가 잡는다. 사람 손 없이 반복한 **127번의 시도에서 117번 잡았고(92%), 116번 반대편 트레이까지 옮겨 놓았다(91%)**. 다음은 [시뮬 5](05-sim-valve.md)의 밸브 인식과 원 궤적을 이 구성에 붙여 실물 밸브를 돌리는 것이다.

## 카메라 보정: eye-to-hand에서 eye-in-hand로

카메라가 본 픽셀을 로봇 좌표로 바꾸려면 두 가지를 알아야 한다. 카메라 자체의 성질(**내부 보정**: 초점거리, 화면 중심, 렌즈 왜곡)과, 카메라가 로봇 기준으로 어디서 어느 쪽을 보는지(**외부 보정**)다. 두 방식을 차례로 썼다.

| | eye-to-hand (고정 카메라) | eye-in-hand (손목 카메라) |
|---|---|---|
| 카메라 | OBSBOT Tiny 2 Lite (4K 팬틸트 웹캠, RGB만) | Intel RealSense D435i (RGB + 깊이) |
| 달린 곳 | 트레이 위 프로파일 기둥에 고정 | 그리퍼 쪽 손목, 팔과 같이 움직임 |
| 내부 보정 | 체커보드 37장으로 직접 보정, RMS 0.69 px | 공장값 사용, 깊이는 컬러에 정렬 |
| 외부 보정 | solvePnP → 로봇 베이스 기준 카메라 자세 | hand-eye 보정(AX = XB) → 손목(link8) 기준 카메라 자세 |
| 정확도 | 보정에 안 쓴 점으로 검증 5.6–29.8 mm (평균 약 23 mm) | 하나씩 빼고 검증 7.0 mm, 1.2° |
| 높이 | 깊이가 없어 "물체는 트레이 바닥 높이"라고 가정 | 깊이로 면을 3D로 찾음 |

### 1. 고정 카메라 (eye-to-hand)

트레이 두 개가 다 보이게 위에서 내려다보는 카메라를 고정했다. 카메라가 움직이지 않으니 로봇 베이스에 대한 자세를 한 번만 구하면 된다.

- **내부 보정:** 16 mm 체커보드를 화면 곳곳에서 기울여 찍고, 코너를 찾아 `cv2.calibrateCamera`로 초점거리·주점·왜곡을 구했다.
- **외부 보정:** 보정 점의 로봇 좌표를 **그리퍼 손끝으로 직접 찍어서** 얻고, 사진 속 픽셀과 짝지어 `solvePnP`에 넣었다. 그러면 카메라 자세가 바로 로봇 베이스 기준으로 나온다.
- **보정 점 고르기:** 처음엔 25 mm ArUco 마커 하나의 네 모서리를 썼는데, 마커 위는 맞아도 15–20 cm 떨어진 곳은 11–13 cm 틀렸다. 점들이 2.5 cm 안에 몰려 있으면 각도의 작은 오차가 거리에 비례해 커지기 때문이다. 그래서 두 트레이에 걸치는 큰 체커보드(코너 54개, 약 22 × 13 cm)의 **네 모서리만 손끝으로 찍고, 나머지 50개 코너는 쌍선형 보간**으로 채워 solvePnP에 넣었다. 찍는 수고는 같고 점은 작업 영역 전체에 퍼진다.
- **픽셀 → 로봇 좌표:** 깊이가 없으니 픽셀의 왜곡을 지운 뒤 카메라에서 그 방향으로 뻗는 광선을 만들고, 그 광선이 트레이 바닥 평면(z = 0.0222 m)과 만나는 점을 물체 위치로 썼다.

이 방식으로 라이브 검출 → 집기 → 놓기까지 됐다. 하지만 두 가지가 걸렸다.

- **팔이 시야를 가린다.** 카메라가 트레이 위에서 내려다보니, 팔이 물체 위로 다가가는 순간 팔과 그리퍼가 물체를 가린다. 정작 잡기 직전에 위치를 다시 확인할 수 없다.
- **깊이가 없다.** 물체 높이를 "트레이 바닥"으로 가정해야 했고, 위치 정확도도 평균 약 23 mm였다.

그 밖에 이 카메라는 AI 사람 추적 기능이 켜져 있으면 짐벌이 스스로 조금씩 움직여 보정이 틀어졌다. 추적을 끄고 짐벌 각도와 해상도를 매번 같은 값으로 고정하는 절차를 만들었다.

### 2. 손목 카메라 (eye-in-hand)

그래서 깊이 카메라를 그리퍼 쪽 손목에 달았다. 카메라가 팔 끝에 있으니 팔에 가려지지 않고, **목표 바로 위로 가서 거의 수직으로 다시 볼 수 있다**(아래 "위에서 다시 보기"). 대신 카메라가 팔과 같이 움직이므로 베이스가 아니라 **손목에 대한** 카메라 자세를 구해야 하고, 이것이 hand-eye 보정이다.

- **샘플 모으기:** 체커보드를 테이블에 고정하고 로봇을 20가지 자세로 옮기며 찍었다. 샘플마다 사진이 찍힌 바로 그 시각의 손목 자세(TF)와, 사진에서 solvePnP로 구한 보드 자세를 짝지어 저장했다. 손목 방향을 크게 바꿔야(최대 86°) 회전이 잘 풀린다.
- **나쁜 샘플 거르기:** 0.5초 동안 손목이 1 mm·0.5° 넘게 움직였거나, 코너 70개를 다 못 찾았거나, 보드 재투영 오차가 1.5 px를 넘으면 저장하지 않았다.
- **풀기:** OpenCV의 풀이 5가지(TSAI, PARK, HORAUD, ANDREFF, DANIILIDIS)를 모두 비교했다. PARK, HORAUD, ANDREFF가 1 mm 안쪽으로 같아서 PARK를 썼다.
- **검증:** 고정된 보드의 위치를 20개 자세 각각에서 계산하면 평균 6.6 mm 안에 모였고, 하나씩 빼고 다시 보정해 뺀 자세를 예측하면 7.0 mm, 1.2°였다. 보정에 안 쓴 새 자세 두 개끼리는 6.0 mm, 3.5°였다. 카메라가 link8에 대해 z축으로 약 44.5° 돌아가 나왔는데, Franka Hand가 link8에 45° 돌려 달려 있는 것과 맞는다.
- **높이는 실측:** 수평 위치와 회전은 쓸 만했지만 높이 방향 오차가 커서, 높이는 손끝으로 잰 트레이 바닥과 큐브 크기로 고정했다.

??? 원리: hand-eye 보정 (AX = XB)
    베이스에서 보드까지는 `베이스 → 손목(관절값으로 앎) → 카메라(X, 모름) → 보드(사진으로 봄)`로 이어진다. 보드는 고정돼 있으니 어느 자세 i에서 계산해도 base_T_board가 같아야 한다.

    base_T_link8(i) · X · camera_T_board(i) = base_T_link8(j) · X · camera_T_board(j)

    정리하면 A = base_T_link8(j)⁻¹ · base_T_link8(i) (손목이 움직인 양), B = camera_T_board(j) · camera_T_board(i)⁻¹ (카메라가 본 보드의 움직임)로 **AX = XB** 꼴이 된다. 자세 쌍이 많을수록, 특히 회전축이 다양할수록 X가 잘 정해진다.

??? 원리: solvePnP와 기준선
    3D 점들의 좌표와 그 점들이 찍힌 픽셀을 알면 카메라의 회전 R과 위치 t를 구할 수 있다(PnP 문제). 구한 R, t로 3D 점을 다시 화면에 그렸을 때 실제 코너와의 차이가 재투영 오차다. 다만 재투영 오차는 보정에 쓴 점에 대한 값이라, 실제 정확도는 보정에 안 쓴 점으로 따로 재야 한다. 점들이 좁은 곳에 몰리면 R의 작은 오차를 구분하지 못하고, 그 오차가 거리에 비례해 위치 오차로 커진다. 마커 하나로는 안 되고 넓게 퍼진 체커보드가 필요했던 이유다.

## 목표 검출

손목에 단 RealSense D435i의 컬러와 깊이로 큐브 **윗면**을 찾는다. 큐브는 옆면도 40 mm 정사각형이라, "정사각형 찾기"만으로는 윗면과 옆면을 구분할 수 없다. 그래서 깊이로 면을 3D 평면으로 맞추고 그 기울기를 본다.

1. **후보 찾기:** 컬러 영상에서 어두운 덩어리(검은 큐브)를 찾는다.
2. **같은 높이 픽셀만 잇기:** 후보 안의 한 점에서 시작해 깊이 차이가 ±3 mm 이내인 픽셀만 이어 붙인다. 윗면과 높이가 다른 옆면·트레이 바닥이 여기서 떨어져 나간다.
3. **3D로 되돌리기:** 픽셀 좌표 + 깊이 + 카메라 내부 파라미터로 카메라 기준 3D 점을 만들고, hand-eye 보정값으로 로봇 베이스 기준으로 옮긴다.
4. **평면 맞추기:** 점들에서 평균을 빼고 SVD를 하면, 가장 작은 특이값의 방향(점들이 가장 덜 퍼진 방향)이 면의 법선이다.
5. **윗면인지 검사:** 법선이 수직에서 20° 넘게 기울었으면 옆면으로 보고 버린다.
6. **크기와 회전각:** 점들을 위에서 내려다본 2D로 보고 감싸는 최소 면적 사각형을 구한다. 변 길이로 40 mm 정사각형인지 확인하고, **변의 방향이 그대로 그리퍼를 돌릴 각도**가 된다.

비스듬히 보면 카메라에서 먼 쪽 가장자리의 깊이가 흐려져 2단계에서 빠지고, 윗면이 30–35 mm로 잘려 중심이 카메라 쪽으로 밀린다. 모자란 길이만큼 사각형을 카메라 반대쪽으로 늘려 보정했지만 충분하지 않아서, 아래의 **위에서 다시 보기**를 더했다.

높이(Z)는 hand-eye 보정 오차가 가장 큰 방향이라 보정값 대신 직접 잰 트레이 높이와 큐브 크기로 정하고, 보정값은 수평 위치와 회전에만 쓴다.

### 좌표 변환

| 단계 | 변환 | 구한 방법 |
|---|---|---|
| 픽셀 + 깊이 → 카메라 좌표 | 핀홀 모델 | 카메라 내부 파라미터 |
| 카메라 → 손목(link8) | `link8_T_camera` | hand-eye 보정 (위) |
| 손목 → 로봇 베이스 | `base_T_link8` | 그 순간의 관절값으로 계산 (TF) |
| 그리퍼 끝(TCP) ↔ link8 | 10.34 cm 오프셋 | 목표는 그리퍼 끝 기준으로 받고, IK 직전에 link8 기준으로 바꿈 |

## 잡는 방식

| 단계 | 동작 | 경로 |
|---|---|---|
| 1 | HOME에서 큐브 검출 | |
| 2 | 큐브 위로 이동 | OMPL (자유공간 계획) |
| 3 | **바로 위에서 다시 검출**해 위치·회전각 갱신 | |
| 4 | 그리퍼를 회전각에 맞춰 돌린 채 **직선 하강** → 힘을 주며 잡기 → 직선 상승 | Cartesian path |
| 5 | 반대편 트레이의 놓을 곳 위로 이동 → 직선 하강 → 놓기 → 직선 상승 | OMPL + Cartesian path |
| 6 | HOME으로 돌아와 다시 검출하고 놓인 위치 확인 | |

- **위에서 다시 보기:** 큐브 바로 위에서는 카메라가 거의 수직으로 내려다봐서 윗면이 덜 잘리고, 큐브가 화면 가운데 크게 잡힌다. HOME에서 비스듬히 본 값으로 내려가면 늘 로봇 쪽 가장자리를 잡던 문제가 이걸로 해결됐다. 다시 보기에 실패하면(크기 검사에 걸리는 경우 등) 8초 뒤 HOME 검출값으로 진행해 반복이 멈추지 않게 했다.
- **목표 근처는 직선으로만:** 자유공간 계획(OMPL)은 도착만 보장하고 중간 경로는 매번 다르다. 짧은 하강에서도 손목이 크게 돌아서, 큐브 위에서부터는 손끝이 직선으로만 움직이는 Cartesian path를 쓴다. 직선 경로가 99.9% 미만으로 만들어지면 실행하지 않는다.
- **안전:** 실물 테이블과 레일을 잰 충돌 모델을 넣고, 목표는 테이블 위 3 cm 여유를 따로 검사한다. 팔 컨트롤러는 움직일 때만 켜고, 모든 이동은 계획을 먼저 보여 준 뒤 실행한다.

## 자동 반복 결과

1–6을 사람 손 없이 반복했다. 놓은 쪽이 다음 회차의 집는 쪽이 되어 양쪽 트레이를 오간다. 이 반복은 모방학습 데이터를 모으는 용도도 겸해서, 경로 중간점에 ±1 cm(높이 ±1.5 cm), 속도에 0.7–1.2배의 **무작위 노이즈를 일부러 넣었다**.

| 항목 | 결과 |
|---|---|
| 기록된 회차 | 132회 |
| 실제 시도 | 127회 (움직이기 전에 멈춘 5회 제외: 큐브가 예상과 다른 트레이에 있어 시작하지 않음 3, 사람이 멈춤 1, 프로그램 종료 1) |
| 잡기 성공 | **117 / 127 (92%)**. 놓친 10회 중 2회는 큐브가 트레이 가운데 볼트 위에 기울어져 놓여 있던 경우 |
| 반대편 트레이까지 옮겨 놓기 | **116 / 127 (91%)**. 잡은 뒤 1회는 이동 경로 실행 오류 |
| 놓은 뒤 확인 | 116회 중 113회 확인, **모두 목표 트레이 위**. 3회는 확인 사진에서 큐브 검출이 안 됨 |
| 놓은 위치의 목표 대비 오차 | 평균 14 mm (중앙값 12.5 mm, 최대 37 mm) |
| 오차 25 mm 이내 | 96회. 모방학습 시연 데이터로 고른 기준 |
| 1회 평균 시간 | 약 49초 |

오차 25 mm는 모방학습에 쓸 깔끔한 시연을 고르려고 정한 엄격한 기준이다. 확인된 113회 중 이 기준을 넘은 17회도 모두 큐브를 목표 트레이 위에 정상적으로 옮겨 놓은 경우다.

## 밸브 조작으로 이어지는 점

| FR3에서 만든 것 | 밸브 조작에서 쓰는 곳 |
|---|---|
| 팔에 가리지 않는 손목 카메라 | 밸브 바로 앞에서 손잡이를 가리지 않고 보기 |
| 깊이 평면 맞추기로 면의 법선과 중심 구하기 | 밸브 면의 법선과 중심 (시뮬 5와 같은 방식) |
| 손목 카메라 → 로봇 좌표 변환 (hand-eye) | 밸브 중심·법선을 로봇 좌표로 옮기기 |
| 목표 바로 위(정면)에서 다시 보기 | 밸브 정면에서 다시 보고 손잡이 위치 보정 |
| 정렬한 뒤 직선으로만 접근 | 밸브 면에 수직으로 손잡이까지 곧게 접근 |
| 작업 후 다시 보고 확인 | 밸브가 실제로 돌았는지 확인 |

## 트러블슈팅

!!! issue "실물 충돌"
    **문제** 시험 중 손목이 테이블 위 알루미늄 레일에 닿아 비상정지했다.

    **원인** 충돌 모델에 레일이 없었고, 로봇 베이스 위치도 실제와 16 cm 어긋나 있었다.

    **해결** 실물을 재서 테이블과 레일을 충돌 모델에 넣고 베이스 위치를 바로잡았다.

!!! issue "옆면을 윗면으로 착각"
    **문제** 검출된 정사각형이 큐브 윗면이 아니라 옆면일 때가 있었다.

    **원인** 옆면도 40 mm 정사각형이라 크기만으로는 구분되지 않는다.

    **해결** 깊이로 맞춘 평면의 법선을 보고, 수평에서 20° 넘게 기운 면은 버린다.

!!! issue "그리퍼 끝으로 목표를 주면 IK가 실패"
    **문제** 목표를 그리퍼 끝 기준으로 주면 경로 계획이 실패했다.

    **원인** IK는 손목 끝 링크(link8) 기준으로만 풀린다. 그리퍼 끝은 link8에서 10.34 cm 앞이다.

    **해결** 목표는 그리퍼 끝 기준으로 받고, IK 직전에 link8 기준으로 바꾼다.
