!!! summary "한 줄 요약"
    다리 하나의 주 모터·보조 모터·엔코더를 다리 모듈 하나로 묶고, 네 다리를 ROS 2 토픽으로 늘이고 줄이는 제어 노드를 만들었다. 움직이기 전과 0.1초마다 엔코더 각도를 확인해서 **리밋을 넘거나 각도를 못 읽으면 바로 멈춘다.** 처음 버전은 엔코더를 못 읽으면 검사를 건너뛰고 계속 움직였는데, 이를 고치고 실제 장치 없이 테스트로 확인했다.

## 한 일

- 다리 모듈: 다리 하나의 늘이기·줄이기·정지·리밋 감시
- 리프트 컨트롤러: CAN·DXL·엔코더 포트를 열고 네 다리 조립, 0.1초 감시 루프
- ROS 2 제어 노드: `/robot/lift_command` JSON 명령 받기, `/robot/lift_status` 발행
- 원격 제어 화면: 다리별 신장·수축·정지, 전체 정지
- 오류 수정: 엔코더 실패 시 정지, 다리별 엔코더 주소, 공유 버스 잠금, 정지 실패 격리
- 실제 장치 없이 안전 규칙을 확인하는 테스트

## 구조

```text
RobotControllerNode   /robot/lift_command 구독, /robot/lift_status 발행
   └─ LiftController  포트 열기, 0.1초 리밋 감시, 전체 정지
        └─ LiftModule × 4 (front_left, front_right, rear_left, rear_right)
             ├─ LiftMotor      AK80-64, CAN (ERPM)
             ├─ DynamixelMotor 보조, RS-485 (전류)
             └─ 엔코더         AMT212, RS-485 (각도)
```

두 노드는 `MultiThreadedExecutor` 하나에서 같이 돈다.

## 늘이기·줄이기 순서

| 단계 | 늘이기 (extend) | 줄이기 (retract) |
|---|---|---|
| 1. 각도 읽기 | 엔코더 각도 | 엔코더 각도 |
| 2. 못 읽음 | 두 모터 정지, 거부 | 두 모터 정지, 거부 |
| 3. 리밋 | 150° 이상이면 정지, 거부 | 10° 이하이면 정지, 거부 |
| 4. 보조 모터 | +0.05 A | −0.2 A |
| 5. 주 모터 | +ERPM (기본 500) | −ERPM |

10–150°는 테스트용 값이다. 실제 기구 범위는 아직 재지 않았다.

명령을 한 번 보내면 모터는 그 속도로 계속 돈다. 그래서 리프트 컨트롤러가 0.1초마다 네 다리 각도를 다시 읽어, 리밋에 닿거나 엔코더가 응답하지 않으면 그 다리를 멈춘다.

## 토픽

| 토픽 | 방향 | 타입 | 내용 |
|---|---|---|---|
| `/robot/lift_command` | 구독 | `std_msgs/String` | JSON: `action`, `leg`, `erpm` |
| `/robot/lift_status` | 발행 (0.1초) | `std_msgs/String` | JSON: 포트 연결 상태, 다리별 각도 (못 읽으면 `null`) |

| `action` | 동작 |
|---|---|
| `extend` / `retract` | 해당 다리 늘이기 / 줄이기 |
| `stop` | 해당 다리 정지 |
| `stop_all` | 네 다리 모두 정지 (`leg` 없어도 됨) |

```bash
ros2 topic pub --once /robot/lift_command std_msgs/msg/String \
  '{data: "{\"action\": \"extend\", \"leg\": \"front_left\", \"erpm\": 500}"}'
```

## 장치가 일부 없어도 켜진다

CAN, Dynamixel 포트, 엔코더 포트를 **각각 따로** 열고, 실패하면 오류만 남기고 다음으로 넘어간다. 연결 상태는 `/robot/lift_status`의 `connections`에 실린다. 엔코더 포트가 없으면 각도를 못 읽으니 모든 이동 명령이 거부된다. 하나만 연결해도 상태를 확인할 수 있고, 위험한 쪽(엔코더 없이 움직이기)으로는 가지 않는다.

## 장치 없이 안전 규칙 검증

모터·직렬 포트를 가짜 객체로 바꿔, 실제 장치 없이 안전 규칙을 테스트로 확인했다.

- 엔코더가 없거나 움직이는 중에 끊기면 두 모터가 정지한다.
- 리밋에 닿은 쪽으로는 움직이지 않고, 정상 각도에서만 움직인다.
- 통신 오류 뒤에도 포트 설정이 원래대로 돌아온다.
- 장치가 일부 없어도 컨트롤러가 켜진다.
- 웹 UI는 포트를 닫기 전에 전류를 0으로 보내고, 수신 오류가 나면 모터를 멈춘다.

## 트러블슈팅

!!! issue "엔코더를 못 읽으면 리밋 없이 계속 움직임"
    **문제** 엔코더 응답이 끊기면 리밋 검사를 건너뛰고 모터가 계속 돌았다.

    **원인** 각도를 못 읽었을 때(값 없음) "리밋에 안 걸렸다"로 처리했다. 읽기 실패와 정상 범위를 구분하지 않았다.

    **해결** 각도를 못 읽으면 움직이기 전에도, 감시 루프에서도 두 모터를 정지시키고 실패를 돌려준다.

!!! issue "네 다리가 같은 엔코더 주소를 씀"
    **문제** 다리마다 다른 엔코더를 읽어야 하는데 네 다리가 같은 주소로 요청하고 있었다.

    **원인** 다리 모듈을 만들 때 엔코더 주소를 넘기지 않아 모두 기본값 `0x54`를 썼다.

    **해결** 설정의 다리별 요청 바이트(`0x1C`, `0x2C`, `0x3C`, `0x4C`)를 넘기게 했다.

!!! issue "엔코더 버스를 동시에 읽음"
    **문제** 감시 루프와 명령 처리가 같은 엔코더 포트를 동시에 쓰면 요청과 응답이 섞일 수 있었다.

    **원인** 네 엔코더가 직렬 포트 하나를 공유하는데 잠금이 없었고, 두 노드가 여러 스레드에서 돈다.

    **해결** 네 다리가 잠금(RLock) 하나를 공유해서 한 번에 한 다리만 요청·응답을 주고받는다.

!!! issue "정지 하나가 실패하면 나머지도 안 멈춤"
    **문제** 전체 정지 중 한 다리에서 통신 예외가 나면 그 뒤 다리는 정지 명령을 못 받았다.

    **원인** 반복문 안에서 예외가 그대로 밖으로 나갔다.

    **해결** 다리마다 예외를 잡아 기록만 하고 다음 다리로 넘어간다. 감시 루프도 같은 방식으로 바꿨다.

!!! issue "통신 오류 뒤 포트 timeout이 바뀐 채로 남음"
    **문제** 엔코더 읽기 중 오류가 나면 포트 timeout이 바뀐 채로 남아 다른 읽기에 영향을 줄 수 있었다.

    **원인** timeout을 바꾸고 되돌리는 코드가 정상 경로에만 있었다.

    **해결** 오류가 나도 반드시 원래 timeout과 수신 방향(RTS)을 되돌린다.

!!! lesson "배운 점"
    - 안전 검사에서 "값을 못 읽음"은 "괜찮음"이 아니라 "멈춤"이어야 한다.
    - 계속 도는 모터는 명령 순간 한 번이 아니라 주기적으로 다시 확인해야 한다.
    - 하드웨어 코드도 통신 객체를 가짜로 바꾸면 테스트할 수 있다. 장치 없이 안전 규칙을 검증할 수 있다.
    - 정지 같은 안전 동작은 하나가 실패해도 나머지가 실행되게 격리한다.

## 남은 점

- 리밋 각도 10–150°를 기구의 실제 범위로 측정해 바꾸기
- 실물 주행·조향 모듈과 안전 컨트롤러 구현. 주행·조향은 지금 외부 드라이버 상태 모니터만 있다.
- 시뮬의 다리 높이 명령(m)을 실물 엔코더 각도(°)로 바꾸는 대응 관계 만들기

## 원리

??? 소프트웨어 리밋과 감시 루프
    리프트처럼 끝이 막힌 기구는 끝을 넘어 계속 돌리면 기구나 모터가 상한다. 리밋 스위치 같은 하드웨어 장치가 없으면 엔코더로 위치를 보고 소프트웨어로 막는다.

    - **명령 시점 검사:** 움직이기 전에 각도를 읽어, 이미 끝에 있으면 그쪽으로는 출발하지 않는다. 방향별로 본다. 최대 끝에서도 줄이기는 된다.
    - **주기 검사:** 속도 명령은 한 번 보내면 계속 유지되니, 0.1초마다 다시 읽어 끝에 닿으면 멈춘다.
    - **실패 = 정지:** 읽기 실패를 정상으로 보면 감시 자체가 꺼진 것과 같다.

    감시 주기 동안 움직이는 거리가 리밋 여유보다 작아야 한다. 속도를 올리면 주기를 줄이거나 리밋 여유를 넓혀야 한다.
