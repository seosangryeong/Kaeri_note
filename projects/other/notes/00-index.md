!!! summary "한 줄 요약"
    다이나믹셀 하나로 여러 단이 직선으로 늘어나고 줄어드는 장치를 **ESP32**로 제어했다. 위·아래 스위치를 누르는 동안만 움직이고, 떼면 토크를 끈다. 처음에는 전류로 원점을 잡은 뒤 **위치 제어**로 움직였고, 나중에 **속도 제어 + 전류 감시**로 바꿨다. 같은 ESP32 + 다이나믹셀 구성에 Wi-Fi 명령을 붙여 **문 열기 모듈**과 **후크 모듈**도 만들었다.

## 구성

| 구성 | 내용 |
|---|---|
| 컨트롤러 | ESP32 (NodeMCU-32, ESP-WROOM-32) |
| 액추에이터 | ROBOTIS 다이나믹셀 X 시리즈 (12 V, 외부 전원) |
| 통신 변환 | MAX485: ESP32의 UART를 다이나믹셀의 RS-485로 바꿈 |
| 입력 | 위/아래 스위치 (가운데가 GND) |
| 전원 | 리튬폴리머 배터리 + 잔량 표시기 |
| 라이브러리 | [hideakitai/Dynamixel](https://github.com/hideakitai/Dynamixel) (Arduino IDE) |

## 배선

| ESP32 | 연결 | 비고 |
|---|---|---|
| GPIO18 | 스위치 up | 내부 풀업, 누르면 LOW |
| GPIO19 | 스위치 down | 내부 풀업, 누르면 LOW |
| GND | 스위치 가운데 | |
| GPIO23 | MAX485 DE, RE | 송신/수신 전환 |
| GPIO17 (TX) | MAX485 DI | |
| GPIO16 (RX) | MAX485 RO | |
| 3V3 / GND | MAX485 VCC / GND | |
| | MAX485 A, B → 다이나믹셀 DATA+, DATA− | 다이나믹셀 전원은 외부 12 V |

스위치는 누르는 방향과 연결된 단자가 반대로 되어 있어서, 배선할 때 up/down을 바꿔 물려야 한다. 최종 코드는 스위치를 GPIO13/12에, 다이나믹셀 시리얼을 GPIO18(RX)/19(TX)에 두었다.

## 제어 방식

| 버전 | 운전 모드 | 동작 |
|---|---|---|
| 1차 | PWM → 확장 위치 제어 | 켜지면 PWM으로 아래로 밀다가 끝에 닿아 전류가 임계값(−230)을 넘으면 멈추고, 그 자리를 원점으로 잡는다(homing offset). 스위치를 누르는 동안 목표 위치(위 150000, 아래 0)로 간다 |
| 2차 | 속도 제어 | 스위치를 누르는 동안 속도 ±120으로 움직인다. 현재 전류가 범위(−300 ~ 400) 밖이면 토크를 끈다 |

위치 제어 버전은 켤 때마다 원점을 다시 잡아야 했다. 속도 제어 버전은 원점이 필요 없는 대신 위치 한계도 없어서, 끝에 닿은 뒤에도 계속 밀게 된다. 그래서 **전류로 끝단과 걸림을 감지**해 토크를 끄도록 했다.

## 같은 구성으로 만든 모듈

ESP32를 고정 IP로 Wi-Fi에 붙이고 TCP 서버(포트 9000)를 열어, 한 줄짜리 문자열 명령을 받아 모터를 움직인다. 다이나믹셀과 MightyZap 선형 액추에이터가 같은 RS-485 버스(Serial2)를 함께 쓴다.

| 모듈 | 명령 | 동작 |
|---|---|---|
| 문 열기 | `ext` / `con` | 다이나믹셀(ID 21, 확장 위치 제어)로 팔을 뻗고 접음 (15000 / 500) |
| | `door_h_r` / `door_h_l` | 다이나믹셀(ID 20)로 손잡이를 오른쪽/왼쪽으로 돌림 |
| | `cling_on` / `cling_off` | MightyZap(ID 0)으로 붙잡기 / 떼기 |
| | `grip` / `release` | MightyZap(ID 11)으로 쥐기 / 놓기 |
| | `dxl_t_on` / `dxl_t_off` | 다이나믹셀 토크 켜기 / 끄기 |
| 후크 | `hook` / `unhook` | 다이나믹셀(ID 23, 위치 제어)로 문고리 걸기 / 풀기 |

Wi-Fi 없이 시험할 때는 시리얼 모니터에서 숫자 키(1–0)로 같은 동작을 하는 버전을 썼다.

!!! issue "왼쪽 손잡이 명령이 실행되지 않음"
    **문제** `door_h_l`을 보내도 손잡이가 왼쪽으로 돌지 않았다.

    **원인** 처음 코드에서 손잡이 분기의 두 조건이 모두 `door_h_r`로 적혀 있어서, 왼쪽 위치(2450)로 가는 줄에 도달할 수 없었다.

    **해결** 두 번째 조건을 `door_h_l`로 고쳤다(door open v2).

??? 원리: RS-485 반이중과 DE/RE 핀
    다이나믹셀 X 시리즈의 RS-485 모델은 선 두 개(A, B)의 전압 차이로 데이터를 주고받는다. 한 선로로 보내기와 받기를 번갈아 하는 반이중 방식이라, 지금 보낼 차례인지 받을 차례인지 정해 줘야 한다.

    MAX485의 DE(송신 허용)와 RE(수신 허용)를 묶어 ESP32 핀 하나(GPIO23)에 연결하고, 라이브러리가 패킷을 보낼 때만 이 핀을 HIGH로 올린다. 코드의 `PIN_RTS = 23`이 이 핀이다.

??? 원리: 다이나믹셀 운전 모드
    `operatingMode()`로 모터가 무엇을 목표로 움직일지 정한다. 모드를 바꿀 때는 토크를 먼저 꺼야 한다.

    | 값 | 모드 | 쓴 곳 |
    |---|---|---|
    | 1 | 속도 제어 | 다단 장치 2차 버전 |
    | 3 | 위치 제어 (한 바퀴 안) | 후크 v2 |
    | 4 | 확장 위치 제어 (여러 바퀴) | 다단 장치 1차 버전, 문 열기 팔 |
    | 16 | PWM 제어 | 원점 잡기 (끝까지 밀기) |

    다단 장치는 모터가 여러 바퀴 돌아야 끝까지 가므로 위치 제어를 쓸 때도 확장 위치 제어(4)를 썼다. homing offset은 읽은 위치에 더해지는 값이라, 끝단에서 읽은 위치를 빼 주면 그 자리가 0 근처가 된다.
